# אתר פיטופוליס · fitopolis.co.il

האתר השיווקי של **פיטופוליס (FITOPOLIS)** — אפליקציה למאמני כושר לניהול
המתאמנים שלהם. אתר סטטי, עברית RTL, מתארח ב-GitHub Pages מאחורי הדומיין
`fitopolis.co.il`.

## מלכודת מטמון — לקרוא לפני שמשנים CSS

GitHub Pages מגיש את `style.css` עם מטמון של 10 דקות, ואי אפשר לשנות את
הכותרות. מי שביקר באתר בעשר הדקות שלפני השינוי יראה **דף חדש עם עיצוב
ישן** — וזה נראה כמו באג חמור (אלמנטים בגודל ברירת המחדל של הדפדפן, בלי
צבע ובלי כרטיסים), בזמן שהקוד תקין לגמרי. קרה בפועל ב-28/08.

**לכן: בכל שינוי ב-`css/style.css` יש להעלות את המספר ב-`?v=`** בקישור
שבחמשת הדפים (`index`, `support`, `accessibility`, `404`,
`invite/index`). הכתובת משתנה, והדפדפן נאלץ להוריד מחדש.
אותו כלל ל-`js/main.js` ול-`js/demo.js` (מקושרים רק מדף הבית): `main.js?v=N`, `demo.js?v=N`.
המצב כרגע: `style.css?v=12` (בכל הדפים, כולל `invite/`), `phone.css?v=2`, `main.js?v=4`, `demo.js?v=4` (09/09/2026, סבב 4).

## הדמו האינטראקטיבי בטלפונים — `js/demo.js` + `css/phone.css` (09/09/2026)

שני הטלפונים בדף הבית הם **אב-טיפוס לחיץ**, לא אנימציה: מצב אחד משותף (`S`)
לשני הטלפונים, כך שסימון ארוחה בטלפון של המתאמן משנה את כרטיס המתאמן אצל
המאמן. כל כפתור נושא `data-act` (`go:`, `tab:`, `flip`, `send:`, `eat:`, `set:`,
`confirm`, `approve`, `pay:`, `weight`, `reset`…) והמסכים נבנים כמחרוזות HTML
מתוך `trainer.screens` ו-`trainee.screens`. **המסכים נבנו לפי מפרטים שנכתבו מקוד
האפליקציה (8 סוכני קריאה, 09/09) — נתוני הדמו, המחרוזות, הסדר והמידות הם של
`lib/screens` ו-`lib/widgets`, ב-dp × 0.78.** ערכת הרכיבים בתוך המסך היא `k-*` ב-`css/phone.css`
(כרטיס 18, כפתור ראשי גלולה, כפתור משני 14, תג סטטוס, אווטאר squircle, כותרת מסך עם קווים,
גיליון FormSheet 90%, טוסט 96dp מעל התחתית); `style.css` שומר רק אטומים לפיסות הסטטיות
בכרטיסי המבנה. **הכללים שמורים מהאפליקציה:** בר
ניווט שמתכווץ סביב הטאב הפעיל (`clip-path` + `transform`, מחושב ב-`fitNav`),
טאב פעיל כתום אצל המאמן ובצבע הדיו אצל המתאמן, בועות צ׳אט בצבע הכותב, סרגל
עליון כמו `app_topbar.dart`. אין תלות בספריות. `prefers-reduced-motion` = החלפה
מיידית בלי סיבוב ובלי פתיחת הבר.

**סבב הביקורת (09/09, צהריים):** אחרי הבנייה, 4 סוכני ביקורת קראו את `lib/**` מול הדמו וסימנו ~60 פערים
(`demo.js` v3 + `phone.css` v2): כרטיס לחיץ הוא `div[role=button]` ולא `<button>` (כפתור בתוך כפתור שבר את
הפריסה), הסרגל העליון נעלם בפרופיל ובשיחה, קרוסלת ההתקדמות עם מסילת ווריאציות (חצים + נקודות), טווח
קלוריות עד שבוחרים מקור, אירובי עם גיליון "כמה עשית?", תפריט אימונים כאקורדיון, בקשת פגישה חוסמת את ה-FAB
עם באנר הסבר, "היסטוריית פעולות" בגיליונות התיאום, הערות ותזכורת בפרופיל. **בלי סכומי כסף בשום מקום**
(הוראת הבעלים). **הגב של הטלפון** (`.dp-back`, `.dp-edge`, `.dp-cam`): זכוכית מט, צלעות מתכת בהירות בקצוות,
אי מצלמה עם שלוש עדשות, לוגו חרוט, והסיבוב מטה את הטלפון ב-9° כדי לחשוף את העובי. **מסכים רחבים:** המכולה
גדלה ל-1400 (≥1440) ו-1560 (≥1800) והטלפון ל-1.12/1.24 — הדף ממלא מסך 1536 ו-1920 במקום לשבת בקופסה של 1280.

**סבב 4 (09/09, ערב) — מבנה מול שלב המוצר:** נוסף מקטע "מי צריך אותך היום — ולמה" (`.triage`) בין ההירו
ל"המבנה המרכזי": למי זה, הכאב, מסך הבית כתור טיפול, קישור הזמנה, מתאמן בלי אפליקציה, שעות ארוחה
מחושבות — כל טענה אומתה בקוד לפני שנכנסה. כרטיס "תיאומים ותקופות" נקרא עכשיו "פגישות ותשלומים".
כל דף טוען `style.css?v=12` (גם `invite/`), הטאבים הסמויים בטלפונים מחוץ למסלול Tab, ומעל כל טלפון
קישור "דלג על ההדגמה". `css/_parked.css` מחזיק את כללי הדף "מי מאחורי זה" שהורד — לא נטען.

## לראות את הדף באמת — צילומי מסך עם Chrome ללא ראש (08/09/2026)

פאנל הדפדפן של Claude לא תמיד מצייר (אנימציות לא מתקדמות, צילומי מסך
נכשלים). **מה שכן מצייר: Chrome המותקן במחשב, במצב ללא-ראש.** שלושה
קבצים עם קו תחתון (Jekyll לא מפרסם אותם) עושים את העבודה מול השרת
המקומי בפורט 8571:

- `_shot.html?w=1280&h=900&t=11&sel=.sides` — טוען את הדף ב-iframe ברוחב
  נתון, **מקפיא את כל האנימציות בשנייה `t` של הלולאה**, גולל לאלמנט
  (`sel`) או לגובה (`y`, או `y=end`), ומאפשר להזריק CSS לבדיקה (`x`).
  **מ-09/09 גם מפעיל את הדמו האינטראקטיבי לפני הצילום:** `a=tab:clients|tab:clients|go:profile`
  (רשימת `data-act` מופרדת ב-`|`, לחיצה כל 120ms; `flip-btn` לוחץ על כפתור הסיבוב),
  `ph=.sides .dp` (איזה טלפון; ברירת מחדל הטלפון בהירו), `at=1800` (מתי להתחיל),
  `js=<קוד>` שרץ בתוך הדף ב-`jsat` (למשל כדי להגדיל אזור: `d.body.style.transform="scale(2) ..."`).
  **מלכודת 1:** במצב ללא-ראש מעברי CSS לא מתקדמים — גלולת הבר "נעלמת" אחרי מעבר טאב.
  זה לא באג: מוסיפים `x=.dp-nav,.dp-tab{transition:none!important}` ורואים את המצב הסופי.
  **מלכודת 2:** `a=` לוחץ על ה-`[data-act]` הראשון במסמך — כפתורים במסך שנושאים אותה פעולה
  כמו הטאב יילחצו במקומו; לכן ניווט מכפתורים הוא `go:` ורק הבר משתמש ב-`tab:`. וגם: "הצצת הגילוי"
  פותחת את הבר ל-1.7 שניות בכניסה — התחל לחיצות ב-`at=3500`.
  **מלכודת 3:** `--virtual-time-budget` לא מקדים אנימציות CSS (רק טיימרים). כדי לראות פריים באמצע הסיבוב
  מקפיאים אותו: `x=.dp.is-turning{animation-play-state:paused!important;animation-delay:-0.4s!important}` + `a=flip`.
  **מלכודת 4:** `a=` לוחץ רק אם ה-`data-act` קיים במסך הנוכחי — `go:workout` מהבית לא עושה כלום (שם הכפתור הוא
  `go:workouts`); צילום שנראה "לא השתנה" = הפעולה לא נמצאה, לא באג בדמו.
- `_og.html` — קומפוזיציית תמונת השיתוף (1200×630, מצולם ב-2x).
- `_icon.html?n=192` — האייקון למסך הבית, מיושר לפינה (Chrome לא יורד
  מתחת לגודל חלון מינימלי, אז מצלמים את הפינה השמאלית-עליונה).

הפקודה:
```
chrome.exe --headless=new --disable-gpu --hide-scrollbars --window-size=1280,900 --virtual-time-budget=8000 --screenshot=out.png "http://localhost:8571/_shot.html?w=1280&h=900&t=11&sel=.sides"
```
`--virtual-time-budget` מריץ את הטיימרים והגופנים לפני הצילום. את הקובץ
פותחים עם כלי ה-Read — ורואים. **זה מה שהפך את "לא מספיק טוב" למשהו
שאפשר לעבוד עליו.**
